# 演进方向

## 当前主线

`micro-go` 是复制后在同一 Go Module 内继续开发的单进程应用脚手架。主线是先保证静态依赖
图、配置、生命周期、错误和验证闭环，再由真实业务需求推动能力扩展。Kernel 永远属于应用
内部实现，不重新开放为需要跨项目兼容的框架 SDK。

## 新能力进入方式

1. 从真实调用方、资源所有权和失败语义开始定义需求。
2. 优先选择标准库、仓库现有能力或维护成熟的第三方技术。
3. 业务只依赖项目定义的 Capability，第三方实现放入 `pkg/adapter`。
4. 需要参与配置或生命周期时，由 Bootstrap 使用私有桥接接入内部 Kernel。
5. 同步增加故障注入、边界门禁、运行验证和当前状态文档。

## 明确非目标

- 不提供外部框架 SDK 或跨 Module 的 Kernel 兼容承诺。
- 不提供运行时 Resolve、自动扫描、字段注入、动态代理或动态插件系统。
- 不预建没有调用方的 HTTP、数据库、缓存、消息和分布式治理层。
- 不用多 Scope、实例代际或局部图重建掩盖尚未出现的业务需求。

如果未来真实应用证明失败退出式 Reload 无法满足可用性目标，应先补充量化验收条件，再用
新 ADR 决定两阶段提交或实例代际替换；不得在当前模型旁长期保留第二套 Runtime。
